收缩链
原题　给一条单链表的 head，返回中间节点；偶数长度时返回中间两个里的前一个（1→2 返回 1，1→2→3→4 返回 2）。
收缩 ⓪
「找中间节点」→「偶数长度时找中间两个里的前一个」没说这环
examples 里 1→2 return 1 和 1→2→3→4 return 2 已经把输出定死了。这不是边界，这是输出的定义本身。
你直接从 ① 开始讲，把这一环当成 example 读过去了——从题目里读到答案，不等于你说出了那个约束。面试官不会给你 examples。
这一环卡的不是代码，是七步：它同时是 STEP 2 缺的约束和 STEP 3 该问的真问句
收缩 ①
找中点 → 找「走到一半的位置」
链表不能随机访问，不先数一遍就拿不到 n，也就没法算 n/2。但「一半」这个概念不需要知道 n——只要有一把走两倍速的尺子。这一环你说得很清楚：two pointers, fast and slow, both starting at the head。
O(n)　一趟，不用先数长度
收缩 ②
找一半 → fast 每次两步、slow 每次一步，fast 到头时 slow 正好在中点
不变量：slow 走过的步数永远是 fast 的一半。所以 fast 停在哪，slow 就在哪的一半。步长和起点你都说到了。
O(n)　空间 O(1)
收缩 ③
「fast 到头」到底是哪一刻 —— 这一环是这题的全部
奇数和偶数，fast 停的位置不一样：
· 奇数 1→2→3→4→5：fast 停在最后一个，fast.next == null
· 偶数 1→2→3→4：fast 停在倒数第二个，fast.next.next == null
要拿前一个中点，两种停法都得管，所以循环继续的条件是三个都成立。这一环你说对了——"two conditions, which means the list might have an odd number of nodes or an even number of nodes"——这就是今天一遍 AC 的原因。
O(1)　这一环说满了，代码就没有可挂的地方

可以带走的自检信号

做链表题，第一句真问句永远是：偶数长度的时候，中间那两个我要哪一个？

有效是因为：链表题里的「两个节点」不是边界，是输出定义的最小样本。奇数长度题目自己会说清楚，偶数长度必须问——而且这题的循环条件是三个还是两个，完全由这个答案决定。

例外：题目明确保证长度为奇数时跳过。反过来也成立：如果你发现自己在循环条件里写了第三个判断，回头问自己「它是为哪个偶数情况准备的」——答不上来就是多写了。

代码 · AC 版

public ListNode middleNode(ListNode head) {
  ListNode fast = head;
  ListNode slow = head;

  // 三个判断，各管一件事：
  //   fast != null           挡住空链表（唯一还需要挡的东西）
  //   fast.next != null      奇数长度在这里停，fast 落在最后一个
  //   fast.next.next != null 偶数长度在这里停，fast 落在倒数第二个
  while (fast != null && fast.next != null && fast.next.next != null) {
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow;
}
// TC O(n)　SC O(1)
// 对照：如果题目要的是「后一个」中点（1→2 返回 2，1→2→3→4 返回 3）
// 条件就只剩两个 —— 这就是 STEP 3 那个真问句为什么必须问
while (fast != null && fast.next != null) {
  slow = slow.next;
  fast = fast.next.next;
}
