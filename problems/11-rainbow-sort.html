代码 · 你的 AC 版（i / j / k）

public int[] rainbowSort(int[] array) {
  if (array == null || array.length <= 1) return array;

  // [0,i-1]=-1　[i,j-1]=0　[j,k]=未知（两端都含）　[k+1,end]=1
  int i = 0, j = 0, k = array.length - 1;

  while (j <= k) {
    if (array[j] == -1) { swap(array, i, j); i++; j++; }  // 换来已知的 0 → 走
    else if (array[j] == 1) { swap(array, j, k); k--; }        // 换来未知的 → 不动
    else j++;
  }
  return array;
}
// TC O(n)　SC O(1)

代码 · 官方参考版（neg / zero / one）

// three bounds:
// 1. the left side of neg is -1   (exclusive of neg)
// 2. the right side of one is 1   (exclusive of one)
// 3. the part between neg and zero is 0  (exclusive of zero)
// 4. between zero and one is to be discovered  (INCLUSIVE of both)  ← 你差的那一格
int neg  = 0;
int one  = array.length - 1;
int zero = 0;

while (zero <= one) {
  if (array[zero] == -1) {
    swap(array, neg++, zero++);      // 两个一起动
  } else if (array[zero] == 0) {
    zero++;
  } else {
    swap(array, zero, one--);        // zero 不动
  }
}
return array;

两版是同一个算法——你写的不是 brute force。差别只有两处，而且都不在逻辑上：
① 变量名。neg / zero / one 直接说出了「我左边全是这个」，i / j / k 说不出，所以你得靠注释记——而你的注释差了一格。
② 官方没有 preamble、没有外层 while。你那两行 while(array[i]==-1) i++ 和外层循环删掉之后，一样过——这是你自己的检验法：注释掉跑一遍，能过就删。

下一题只带走三件事

  1. 写区间不变量的时候，每一段后面强制标「含 / 不含端点」。官方注释四条标了四条 inclusive / exclusive——那不是啰嗦，那是这题唯一会错的地方。四段一钉死，循环条件用 < 还是 <= 是推出来的，不用试。
  2. 指针用语义名，不用 i / j / k。neg / zero / one、slow / fast、prev / cur——名字本身就是不变量。如果你想不出一个有意义的名字，说明这个指针你还没定义清楚。
  3. 写完循环，把每个改动循环变量的地方圈出来数一遍。循环头一个、分支里一个 = 两个 = 一轮走两格。这类 bug 读代码读不出来，只能数——这次就是它。
