收缩链
原题　给一条单链表的 head，判断它有没有环，返回 true / false。题目额外给了一条假设：链表里没有重复值。
收缩 ①
「有没有环」→「有没有一个节点被走到第二次」
环的定义就是「顺着 next 一直走，会回到走过的地方」。
这里有个分岔，而分岔正是题目那条假设的用处：要知道「走过」，可以记下来（HashSet 存节点，O(n) 空间），也可以用两个速度不同的指针（O(1) 空间）。"no duplicate value" 是给第一条路准备的——存值而不是存引用时才需要它。你选了第二条路，所以这条假设用不上。
这一环决定了后面所有事，也是 STEP 3 该说清的那句
收缩 ②
「有没有节点被走两次」→「fast 会不会追上 slow」
无环时链表是一条直线，快的先到头、永远追不上；有环时两个都进环，跑道有限，快的必然从后面绕回来。这一环你说得很清楚，而且 "if fast falls off the end of the list" 这个说法很地道，不是中式英语。
O(n) 时间　O(1) 空间
收缩 ③
「会不会追上」→「fast 每轮相对 slow 前进正好 1 步，所以一定不多不少地追上」没说这环
不变量：进环之后，fast 和 slow 的距离每轮缩小正好 1。距离是有限的（不超过环长），所以有限轮内必定变成 0——也就是相遇。
为什么必须是「1 步」：如果 fast 每轮多走 2 步，距离每轮减 2，可能从 1 直接变成 −1，跨过去而不相遇。快 1 步就跳不过去。
这一句就是「为什么是这个停法」，也是 Floyd 这个名字的全部内容。你没说它——所以循环条件里多出一个判断，你也没有工具去发现它是多余的。

· 无环：fast 走到头 → fast == null 或 fast.next == null，这两个就够了
· 有环：slow == fast → return true

代码 · 精简版

public boolean hasCycle(ListNode head) {
  // 不需要特判：head==null 被条件① 挡住，单节点被条件② 挡住
  ListNode slow = head;
  ListNode fast = head;

  // 条件①：奇数长度走到头　条件②：偶数长度走到头
  // 有环时这两个永远不成立 —— 循环只能从下面的相遇出去
  while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;   // 比引用，不比值 —— 所以「无重复值」用不上
  }
  return false;
}
// TC O(n)　SC O(1)
// 为什么相遇检查必须放在移动之后，不能放在前面：
// slow 和 fast 一开始就都在 head，先检查的话第一轮就 slow==fast，任何链表都返回 true。
// 这也是「一个节点指向自己」那个用例真正能测到的东西。
