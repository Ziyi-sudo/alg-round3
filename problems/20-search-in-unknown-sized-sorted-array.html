收缩链
原题　升序 dictionary，长度未知。返回 target 的下标，不存在返回 −1。get(i) 越界返回 null。
收缩 ①
长度未知 → 先造一个右边界
从 1 开始倍增，直到 get(right) == null。此时 right 一定越界，且 right < 2n。
这一环你说得很清楚，一次到位。
O(log n)
收缩 ②
有了 [0, right] → 经典二分（模版 A）
但 right 是越界的，所以 mid 也可能越界。这句你没说。
O(log n)
收缩 ③
越界不是特例 → 把 null 当 +∞卡在这
null 和「太大」都往左收，合并成同一条分支。越界这件事从代码里消失了。
不变量：null 只可能出现在右段（升序 + 前缀连续），所以「null → 往左」永远安全。这句是 STEP 4 必须说的，说了就不会写成经典二分。
STEP 7 · 好习惯没延续

你走的例子，又一次绕开了那条坏分支

A = {1, 2, 5, 9}, T = 5 → 倍增到 right=4 → mid=2 → 命中，返回 2

第一轮就撞上答案，cur == null 那条分支一次都没执行。跟 09 完全一样：你走对了例子，但那个例子碰不到你最不确定的那一行。

而 09 那次你其实做对了一件事——走完主例子之后你主动说 "change the element to three"，换了个输入去覆盖另一条分支。这次没有。那个动作是九题里最成熟的一次测试意识，只出现了一次就消失了。

规则：走例子之前先问自己一句——「我最不确定哪一行？」然后设计一个必须经过那一行的输入。题目自带的例子是用来说明题意的，不是用来测代码的。
这题能打到 null 分支的输入很好造：A={1,2,5,9}, T=100（target 比所有元素都大），或者你自己踩到的 dict=[1], T=2。

可以带走的自检信号

代码里出现「越界 / 不存在 / 特殊值」这种分支时，先问一句——能不能把它翻译成一个普通的值？

越界 = +∞（20）
缺失 = 跳变（08，a[i]−i 从 1 变 2）
峰 = 上升停止（09）

翻译成功之后，predicate 就恢复单调，特殊分支消失，代码短一半。这一章十道题，全在做这一件事。

还有一条老账：这题你写了两个特判，两个都是死代码（dict.get(0)==null 和 get(1)==null）。同一个反射的第三次出现（06 是「先挑第一个」）。检验法：写完特判，注释掉跑一遍，能过就删。

这道题的金句

Out of bounds isn't a special case — it's just a very large value. Treat null as positive infinity and the boundary check disappears.

识别信号：数组长度未知 / 只能通过 API 访问 / 越界有哨兵返回值 → 倍增造右边界，然后把哨兵当极值并进普通比较。

这一套还管：Search in Infinite Stream、找第一个坏版本、以及任何「只给你一个 isBad(i) 的黑盒」的题。

代码 · AC 版

public int search(Dictionary dict, int target) {
  // 两个开头特判都是死代码，删掉了：空字典会在下面自然走到 -1

  int left = 0, right = findRight(dict);

  while (left <= right) {
    int mid = left + (right - left) / 2;
    Integer cur = dict.get(mid);                       // ← 一轮只调一次
    if (cur == null || cur > target) right = mid - 1;  // null 视为 +∞
    else if (cur < target)           left  = mid + 1;
    else                             return mid;
  }
  return -1;
}

// ① 倍增造右边界。返回值是越界的下标 —— 故意的
private int findRight(Dictionary dict) {
  int right = 1;
  while (dict.get(right) != null) right *= 2;
  return right;                     // 无特判：get(1)==null 时循环不进，直接返回 1
}
// TC O(log n)　SC O(1)　get 调用约 2 log n 次
