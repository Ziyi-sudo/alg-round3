收缩链
原题　给一条升序单链表的 head 和一个 value，把 value 插进去、保持升序，返回新的 head。
收缩 ①
「插入一个值」→「找到该改 next 的那个节点」
单链表只能改 next，所以插入这个动作等于「让某一个节点的 next 指向新节点」。问题变成：是哪一个节点？这一环你说得很清楚："I need two pointers, prev and cur, to find the position."
O(n)
收缩 ②
找那个节点 → 一个尾随指针跟着 cur 走
不变量：cur 永远是「第一个还没被判定为小于 value」的节点，prev 永远是它前面那一个。
你说的是 prev.value ≤ value ≤ cur.value——那是条件，不是不变量。差别很关键：不变量描述「每一轮结束后是什么状态」，条件描述「什么时候停」。这条不变量里 prev 只是被动跟着，它的值从头到尾不需要被检查——这就是为什么正确的条件只有一个比较。
O(n)　空间 O(1)
收缩 ③
头可能变 → dummy 提供一个不变的入口卡在这
为什么 dummy 在这题是对的（和 34 正相反）：返回的头可能是新节点（插最前）也可能是原来的 head，但入口在循环开始之前就已知（dummy.next = head）。34 那题返回的头要循环跑完才知道，所以 dummy 无处可放。这个判据你今天用对了。
❌ 卡在下一层：你让 dummy 的值参与了判断。
✅ dummy 只提供 next，它的值永远不被读。new ListNode(0)、甚至无参构造，都一样能过。
判据：dummy 的值如果被读到了，说明你的条件回头看了。
O(1)　这一环是这题的全部
收缩 ④
插入本身 → 两行赋值
node.next = cur;　prev.next = node;　顺序其实无所谓（node 是新的，没人指着它），但先接右边再接左边是更安全的习惯——和 34 里「先存后继再改指针」是同一条肌肉。这两行你一次写对，口述也说对了。
O(1)

代码 · 精简版

public ListNode insert(ListNode head, int value) {
  // dummy 只提供一个不变的入口 —— 它的值永远不被读，写什么都行
  ListNode dummy = new ListNode(0);
  dummy.next = head;

  ListNode prev = dummy;
  ListNode cur  = head;

  // 不变量：prev 是最后一个「值 < value」的节点，cur 是它后面那个
  // 只看 cur，不看 prev —— 所以没有「第 0 次」的问题
  while (cur != null && cur.value < value) {
    prev = cur;
    cur  = cur.next;
  }

  // 退出时 cur 可能是 null（插到尾），也可能是第一个 >= value 的节点
  // 两种情况这两行都对，不需要 post-processing
  ListNode node = new ListNode(value);
  node.next = cur;
  prev.next = node;

  return dummy.next;
}
// TC O(n)　SC O(1)
// 逐个验证，每种情况都不读 prev.value：
// head = null      cur = null，循环 0 轮，dummy.next = node，返回 node        ✓
// 插在最前 (-30)    cur = 1，1 < -30 不成立，0 轮，prev 还是 dummy → 新头      ✓
// 插在中间 (2)      1 < 2 走一步，3 < 2 停 → 接在 1 和 3 之间                  ✓
// 插在最后 (9)      一路走到 cur == null → prev 是尾节点，node.next = null   ✓
// 有重复值 (1,1,3 插 1)  cur = 第一个 1，1 < 1 不成立，停 → 插在相同值之前     ✓

  2. 给 dummy 想「合适的值」= 警报。dummy 只提供 next。一旦你开始纠结它该是 0、−1 还是 MIN_VALUE，停下来看条件，不要看常数。
  3. 走例子必须把常数念出来。你说 "prev's value is less than one" 的时候，屏幕上写的是一个具体数字。手指按住那一行，把数字代进去——这次 trace 通过、提交挂掉，就是因为你代的是性质不是数字。
