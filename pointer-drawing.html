改结构的时候，图为什么会乱

从 34 / 39 / 41 / 653 四次事故里长出来的 · 链表现在管用，树也一样管用
诊断 · 4 题验证

你画的是「链表现在长什么样」，不是「谁指着谁」。前者一改结构就整张作废，后者只需要擦一根箭头。

你画的是状态快照：1→2→3 变成 3→2→1，于是你在纸上把节点搬了位置。节点一搬，所有变量指向哪儿就全乱了，你只能重画。
正确的画法是引用图：节点的位置永远不动，改结构只改箭头和变量标签。这样每一步只擦一两笔，脑子里那张图不会崩。

题你嘴里 / 纸上的图图里少画的那根线
34"…so prev, prev is null, and then prev goes to cur…"prev 那个标签实际贴在 dummy 上，不是 null
39"we find prev's value is less than the insert value one"dummy 里装的那个具体数字，你代的是「它反正比较小」
41merge 循环加了两个「防越界」的条件A 和 B 谁先用完——两条链的长度关系没画
653画了子问题、也画了子问题的返回值，全对head 自己那根 next——你手上还抓着的那根

四次都是同一个形状：你画了「被改的那部分」，没画「没被改的那部分」。而在指针题里，没被改的那部分恰恰是你还能用的东西——它还指着原来那个节点，等着你。

你现在的画法 · 状态快照

翻转前  1 --> 2 --> 3 --> null

翻转后  1 <-- 2 <-- 3      1 --> null
          ^ 位置一个都没动，只有箭头掉头
  • ✓ 每改一步只擦一两笔

  • ✓ 没动过的线还在纸上——它就是你能白拿的东西

三行画法 · 固定动作

第 1 行　节点        1       2       3       null
          位置钉死，全程不动

第 2 行　next 箭头   -->     -->     -->
          会变，改结构就是改这一行

第 3 行　变量标签    ^
                       head
          会移动，用 ^ 指着它现在贴在哪个节点上

唯一的规矩：节点位置永远不动。「改结构」这个动作，在纸上只有两种形态——掉转一根箭头，或者把一个变量标签挪到另一个节点下面。
只要节点不动，你就不会丢线；只要不丢线，「我手上还抓着谁」就一直看得见。

用它重画 653 · 递归反转

━━ 第 1 层：head = 1，准备调用 reverse(head.next) ━━

    1  -->  2  -->  3  -->  null
    ^       ^
   head   head.next     ← 你传进去的就是它


━━ 递归只管方括号里这段，框外一根线都碰不到 ━━

    1  --> [ 2  -->  3  -->  null ]
    ^        这一段进了递归
━━ 返回之后：框里被翻转了，框外那根线原封不动 ━━

    1  --> [ 3  -->  2  -->  null ]
    ^        ^        ^
   head   newHead   head.next     ← 还是 2！而 2 现在是尾

   1 --> 2 这根线，这一层从头到尾没有任何人动过。
   2 原来是子链的头；翻转把第一个变成最后一个，所以 2 成了尾。
   于是：head.next 就是尾。不用找。
━━ 接回来：两笔 ━━

head.next.next = head;          // 尾（2）的 next 指回 1

    1  <--  2   <--  3
    ^                ^
   head            newHead

head.next = null;              // 1 成为新的尾

    3  -->  2  -->  1  -->  null
    ^
  newHead      ← return 它
你问的那个「好神奇」，其实是一句话

你传给递归的那个节点，就是返回结果的尾

reverse(x) 把「从 x 开始的那条链」翻过来。翻转 = 把第一个变成最后一个。
x 原来是第一个 → x 现在是最后一个。
而 x 就是 head.next，因为那正是你传进去的。

所以 head.next.next = head 这一行，读出来是：「让尾的 next 指回我」。它不是一个技巧，是上面那句话的直接翻译。

为什么容易漏：心理上，一旦把子链「交给」递归，就感觉自己撒手了。但你没有——你手上那根绳子还系在子链的旧头上，而它现在成了尾。画图的时候把那根绳子画出来，这件事就再也不会忘。

同一个画法，画迭代 · 34

━━ 初始 ━━

   null     1  -->  2  -->  3  -->  null
    ^       ^
  prev     cur


━━ 一轮之后：next=cur.next; cur.next=prev; prev=cur; cur=next ━━

   null <-- 1       2  -->  3  -->  null
            ^       ^
          prev     cur

   节点 1 位置没动，只有它的箭头掉了头，两个标签各挪一格。


━━ 再一轮 ━━

   null <-- 1  <--  2       3  -->  null
                    ^       ^
                  prev     cur

   循环退出的条件是 cur 走到 null，那时 prev 停在最后一个翻好的节点
   —— 它就是新头。这就是 return prev 的来处。

迭代和递归画出来是同一张图。迭代里 prev 是一个会移动的标签；递归里同一个东西叫返回值，一层一层往上传。所以 34 的迭代版和 653 的尾递归版是同一个算法的两种写法——你手上握着的那个「已翻好的部分的头」，一个用变量存，一个用参数传。

改结构之前的固定自检

动手改任何一根 next 之前，先问两句：

①「这一步之后，谁会指不到了？」——指不到就得先存下来。这是 34 的 next = cur.next、41 的 an = a.next。

②「这一步我没动过哪些字段？」——没动过的还指着原来那个节点，它是你能白拿的东西。这是 653 的 head.next。

警报：在递归里写 while 去「找」什么。递归每一层已经把该给你的都给你了；还要去找，通常说明第 ② 句没问。

一句口诀

节点钉死，只动箭头。
递归撒手的那一刻，
手里还攥着一根绳子。

英文版，可以直接在面试里说出来：
"The node I hand to the recursion comes back as the tail — I never let go of it."

四次事故，忘的是哪根线

题你在改什么结构忘了画的那根线后果
34反转，prev 一路往前挪prev 标签一开始贴在哪个节点上成环，判题报 cycle
39插入，在 prev 和 cur 之间接线dummy 节点里装的那个具体数字挂 3 次，改了 3 次常数
41切链 + 交替穿插两条链的长度关系（差 0 或 1）加了 2 个防御条件，丢节点
653递归返回后接回来head 自己那根 next多走一趟找尾，O(n²)

四次里三次的后果是「多写了东西」而不是「少写了东西」——多一个特判、多两个条件、多一趟遍历、多一个常数。图上少一根线，代码里就多一段。因为你看不见手上已经有的东西，只好重新去弄一个。

树里会变成什么样

树是同一件事，只是每个节点手上有两根绳子（left 和 right），而且——和单链表一样，你没有 parent 指针，所以照样不能往回看。你在 41 说过的那句「in a linked list we only know what is next, we cannot look back」，在树里一字不改地成立。

陷阱一 · 覆盖（34 的树版）
  1. Invert Binary Tree：要交换 left 和 right
  2. node.left = node.right 一写下去，原来的 left 就找不到了
  3. 必须先存：TreeNode tmp = node.left;

→ 就是「先存后继，再改指针」

陷阱二 · 手上还攥着（653 的树版）
  1. Flatten Binary Tree to Linked List
  2. 递归展平了左子树，你需要它的尾才能接上右子树
  3. 别去走——让递归返回尾，或者用 node.left 那根没动过的线找回去

→ 和 653 一模一样，走一趟就是 O(n²)

树的三行画法：第 1 行画节点（钉死，按层排），第 2 行画 left / right 两种箭头（用不同符号区分，比如 / 和 \），第 3 行标变量。规矩不变：节点不动，只改箭头。
树比链表多问一句：「这个递归调用返回给我的，是子树的根，还是别的什么？」——链表里返回的总是新头，树里可能是根、是高度、是尾、是布尔值。返回什么必须在归约里说死，这是你的第 ⑤ 样。

下次画图带走三件事

  1. 节点钉死，只动箭头和标签。不要在纸上把节点搬到「结果里该在的位置」——那是状态快照，一改就全废。变量名写在节点下面，用 ^ 指着。
  2. 改一根 next 之前问「谁会指不到了」，改完之后问「我没动过哪些字段」。前一句救你不丢节点，后一句让你白拿一个已经在手上的东西。
  3. 递归调用画一个方括号，框外的线一根都不要擦。框里交给递归，框外那根 head.next 是你唯一还抓着的绳子——它通常就是答案的一半。
