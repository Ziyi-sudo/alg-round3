代码 · O(n) 版

public ListNode reverse(ListNode head) {
  // base case：空链表和单节点都已经算「翻好了」，也是递归的出口
  if (head == null || head.next == null) return head;

  // 子问题：把 head 后面那条翻转，拿回它的新头
  ListNode newHead = reverse(head.next);

  // 关键：这一层没有人改过 head.next 这个字段
  // 它还指着子链的旧头 —— 而旧头翻转之后就是尾
  head.next.next = head;   // 尾 → head
  head.next = null;       // head 成为新的尾

  return newHead;           // 新头一路原样往上传
}
// TC O(n)　SC O(n)（调用栈）
// 逐层验证 1 → 2 → 3：
// reverse(3) → base case，返回 3
// reverse(2)  head=2, head.next=3, newHead=3
//             head.next.next = head  →  3.next = 2      得到 3→2
//             head.next = null       →  2.next = null
// reverse(1)  head=1, head.next=2, newHead=3
//             head.next.next = head  →  2.next = 1      得到 3→2→1
//             head.next = null       →  1.next = null   ✓

这次的 base case 特判不是死代码。你已经能分清「哪种开头判断是必要的」——没有它递归停不下来。

下一题只带走三件事

  1. 递归调用之后，先问「哪些指针我这一层没动过」。没动过的，还在原地等你，不用去找。在递归里写 while 去「找」东西 = 警报。
  2. 自己说出「可能有问题 / 可能更慢 / 可能挂」之后，下一句必须是「让我看看能不能避开」。不许直接往下写。这是第 2 次了（41 说了 1→2→3 没用，653 说了 O(n²) 照写）——再来一次就是头条。
  3. 递归题的 STEP 5 第三种固定问：「递归只往下走一层的最小输入是什么？」这题是两个节点。最小的非平凡输入，往往就是暴露多余步骤的那一个。
